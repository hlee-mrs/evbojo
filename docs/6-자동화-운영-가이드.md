# 6. 자동 수집·배포 운영 가이드

이 사이트의 데이터는 **이 Mac의 launchd 작업 하나**가 매시간 수집·커밋·배포한다.
Claude 계정/구독과 무관하게 launchd + git + gh 인증만으로 동작하므로,
계정이 바뀌어도 이 문서대로면 그대로 이어받을 수 있다.

## 구성 요소

| 구성 | 위치 | 역할 |
|---|---|---|
| launchd 잡 | `~/Library/LaunchAgents/com.evbojo.updater.plist` | 매시 :10에 run_auto.sh 실행 (사본: `deploy/launchd/`) |
| 실행 스크립트 | `updater/run_auto.sh` | 락 → fetch+rebase → 수집 → 커밋·푸시 → gh-pages 배포 |
| 수집기 | `updater/update.py` | Playwright로 ev.or.kr 크롤 (매시 `--status`, 04시 `--once` full) |
| 실행 로그 | `updater/auto.log` (2000줄 롤링) | 회차별 RUN/OK/FAIL/SKIP 기록 (git 미추적) |
| IndexNow 제출 | `updater/indexnow.py` | 배포 직후, 이번 회차에 바뀐 URL을 api.indexnow.org에 통지(네이버·빙 등) |
| 프리렌더 | `updater/prerender.py` | 지역·차종·시도·모델·브리핑 허브 + **지역 랭킹(`site/region-ranking.html`)** + **홈 접수 일정 카드(`site/index.html` 슬롯)** + sitemap 전량 재생성. lastmod는 내용 해시(수치·칩·뱃지 표기 변형·derived 블록 마스킹)가 바뀐 날만 |
| 정합 검사 | `updater/selfcheck.py` | 회차마다 14종 회귀 검사(`--warn-only`) — 11 sitemap lastmod 당일 비율(≤30%) · 12 지역→해설 링크 · 13 수집 붕괴 · 14 홈 접수 일정 카드 |
| 색인 감시 | `updater/index_watch.py` (`com.evbojo.indexwatch` 07:40) | 편집 URL 54건 URL Inspection 스냅샷 → `updater/reports/index-YYYY-MM-DD.json` |
| 재신청 게이트 | `updater/readiness.py` | index_watch 끝에서 자동 호출. R1~R9 실측 기준으로 GO/WAIT 판정 → `updater/reports/readiness.md`·주간 리포트 섹션 |

## 동작 규칙 (run_auto.sh에 구현됨)

- **중복 방지**: `updater/.auto.lock/` mkdir 락. full이 길어져 다음 회차와 겹치면 SKIP.
- **충돌 방지**: 실행 전 `git fetch` + `rebase --autostash origin/main`. 충돌 시 abort하고 그 회차 스킵.
- **변경 없으면 종료**: `site/data` diff 없으면 커밋·배포 안 함 (커밋이 3시간 간격으로 보이는 이유 — ev.or.kr 데이터가 그 주기로 바뀜).
- **fail-safe**: 수집 실패 시 기존 데이터 유지, 다음 시간 재시도. full 40%↑ 변경은 `_pending/` 보류.
- **배포**: main 푸시 후 `git subtree split --prefix site` → `gh-pages` 강제 푸시 → GitHub Pages 빌드.
- Mac이 잠들면 그 회차는 스킵되고, 깨어날 때 launchd가 1회로 합쳐 실행한다(예측 알고리즘은 불규칙 간격 허용).

## ⚠️ 단일 작성자 규칙

`site/data/history.json`은 **이 Mac이 유일한 작성자**여야 한다.
NAS·GitHub Actions 등 다른 수집 주체를 추가하려면 **먼저 이쪽 launchd를 꺼야 한다**
(동시 기록 시 이력 꼬임 → 예측 기능 오염).

## 재신청 준비도 게이트 (readiness)

- **무엇**: "지금 애드센스 재신청해도 되는가"를 매일 실측으로 판정. 3회 반려의 실제 원인이 '편집 콘텐츠가 색인된 적이 없어 심사 입력에 안 들어간 것'이라, 고치기 전 상태가 재심사되는 실패 패턴을 수치로 막는다.
- **기준(R1~R9)**: 편집 색인률 ≥60% · 해설 색인률 ≥50% · '크롤링됨-미색인' 0건 · selfcheck 위반 0 · 편집 표면 안정 ≥14일 · 검색 클릭 7일 추세 비하락 · sitemap lastmod 당일 비율 <25% · 라이브 status.json ≤3h · **최근 30일 신규 편집 글 ≥3편**(R9, 2026-10-06 추가). 전부 충족해야 **GO**, 미측정은 판정 제외.
- **R5의 '수정'과 '발행' 구분(2026-10-06)**: lastmod가 그 페이지의 JSON-LD `datePublished`와 같은 URL(=새로 발행된 글)은 R5 안정 기간을 리셋하지 않는다. 4차 반려 문구('지속적인 콘텐츠 큐레이션', '꾸준히 운영')에 맞춰 **글은 계속 쌓이되 기존 글은 손대지 않는** 상태를 GO로 보기 위함. 반면 루트 손편집 페이지(about·articles·index 등)를 고치면 그날로 R5가 리셋된다 — 재신청 전 2주는 손편집을 멈춘다.
- **언제**: `index_watch.py` main() 끝에서 매일 07:40 자동. 수동: `/usr/bin/python3 updater/readiness.py --print`(`--no-gsc`=오프라인).
- **결과**: `updater/reports/readiness.md`(표) · `readiness.json` · `readiness-history.jsonl`(일별 1줄) — git 미추적. 주간 GSC 리포트에도 같은 섹션.
- **읽는 법**: WAIT면 '미충족' 목록과 '가장 이른 재신청 검토일'(R5 안정 기간 충족일)을 본다. GO가 떠도 재검토 요청은 사람이 콘솔에서 1회.

## 지역 페이지 → 해설 내부 링크 (prerender)

- 지역 페이지마다 「함께 읽으면 좋은 해설」 섹션: 접수 상태(소진/마감/임박/접수중)별 해설 3편 + 상위 20위면 지역 랭킹·아니면 6편 풀을 지역 코드로 회전 + 계절 슬롯(10월~ 연말 가이드, 11~2월 겨울 주행거리) + 모델 시리즈 2편(1위 모델 + 지역 코드 회전). 제목·요약은 해설 파일의 `<title>`·description에서 읽어 자동 동기(지어낸 요약 없음).
- 배경: 색인된 표면(지역 122곳)에서 해설로 가는 본문 링크가 0 → 해설 22편 중 4편만 색인(2026-08-31). 링크 수는 selfcheck 12번이 지킨다.

## 홈 접수 일정 카드 · 내 지역 카드 · 잔여 추이 (2026-09-29 병합)

- **홈 📅 접수 일정 카드**: `rounds.json` 등록 회차의 접수 시작·마감(앞으로 7일, `build_home_schedule(horizon=7)`)을 prerender가 매시 `site/index.html`의 `<!--sched:start-->…<!--sched:end-->` 슬롯 **안쪽만** 다시 그려 넣는다. 슬롯이 없으면 경고만 남기고 건너뛴다(손편집 마크업 보존). run_auto.sh가 `site/index.html`을 스테이징하므로 카드는 회차마다 배포된다.
- **derived 블록**: 카드 전체가 `<!--derived:start-->…<!--derived:end-->`로 감싸이고 `_mask`가 이 블록을 통째로 제외한다 → 매시 내용이 바뀌어도 루트 `/`의 lastmod·R5(편집 표면 안정)·R7(당일 비율)에 영향이 없다. 슬롯 마커 자체는 해시에 남으므로 마커를 처음 넣은 날 1회만 `/`가 갱신된다(2026-09-29 실측: 새로 '오늘'이 된 URL은 `/` 1건).
- **지역 페이지 상단 회차 한 줄**(`next_round_html`): "추경2차 접수 중 (시작 9/17(목) 10:00 · 마감 11/30(월) 18:00)" — 절대 날짜만, 같은 derived 블록으로 감싸 해시 제외. 템플릿은 `</div>{{NEXT_ROUND}}`처럼 **같은 줄**에 두어 비어 있을 때 출력이 바이트 단위로 동일해야 한다(줄을 바꾸면 122개 지역 lastmod가 일괄 갱신된다 — 첫 빌드에서 실측).
- **클라이언트 부가 기능**(app.js/detail.js, 정적 HTML 무변경): 홈 '내 지역' 카드 KPI·회차 한 줄(`nextRoundText`, prerender의 쌍둥이)·잔여 추이 스파크라인(`sparkline`: history.json 최근 28일 전체 잔여 실측선 + 추가공고 점선, '지난 N일 −N대'만 표기), 지역 페이지 방문 시 `ev.recentRegion` 기록(9999 제외) → 홈 카드 폴백. 모두 예측·D-day 없음(I3).
- **감시**: selfcheck 14번이 슬롯·derived 마커 짝·카드 존재·링크 대상을 매 회차 검사한다. 마커 짝이 어긋나면 `_mask`가 본문을 통째로 삼켜 lastmod가 멈추므로 즉시 고친다.
- **끄는 법**: index.html에서 슬롯 마커 두 줄을 지우면 prerender가 카드 생성을 건너뛴다(경고 1줄). 범위 조정은 `build_home_schedule(..., horizon=N)`.

## 해설 글 시리즈 — `updater/content/articles/*.md` → `site/articles/` (2026-10-06)

- **왜**: 애드센스 4차 반려(2026-09-27 '가치가 별로 없는 콘텐츠', 심사 항목: 고유 가치·꾸준한 운영·지속적 큐레이션·실제 사용자 관심)의 구조적 원인 = 해설 22편이 2026-08-07~08 일괄 게시 뒤 **새 글이 0편**, 색인 표면의 대부분이 프로그램 생성 페이지. 대응은 '실측 데이터로 쓰는 편집 글을 **매주** 발행하는 파이프라인'이다 — 한 번의 손질이 아니라 지속되는 운영 신호를 만든다.
- **원고**: `updater/content/articles/{slug}.md` — 슬러그는 `[a-z0-9-]+`. 프런트매터 `title`·`description`·`publish`(필수, KST 날짜) / `asof`(데이터 기준일)·`crumb`(브레드크럼 짧은 이름)·`sub`(부제)·`kicker`·`h1`·`modified`·`related`(`href|라벨;href|라벨`) 선택. 본문은 `## 소제목`·`**굵게**`·빈 줄 문단·`[텍스트](region:코드|car:id|sido:slug|model:slug|상대경로|https://…)` + **`- ` 불릿 목록·`|` 파이프 표**(2026-10-06 `md_to_html` 확장, 기존 모델 원고는 둘 다 쓰지 않아 출력 불변).
- **발행 게이트(I9)**: `publish`가 KST 오늘보다 미래면 페이지·사이트맵·홈/허브 블록·매니페스트 어디에도 나오지 않는다. 날짜가 오면 그 시각의 봇 회차가 자동 생성·배포한다(시차 발행 = '꾸준히 운영' 신호). 원고 수치는 `asof` 기준으로 고정된 실측값만(I3) — 발행일에 다시 계산하지 않는다.
- **산출**: `site/articles/{slug}.html`(`article.tpl` + `page.tpl`, Article·BreadcrumbList JSON-LD에 실제 `datePublished`/`dateModified`, 광고 1은 두 번째 카드 뒤·광고 2는 끝 — 모두 `ad_slot` 1,200자 게이트), `site/data/articles.json`(발행분 매니페스트, 최신순), 홈 `<!--latest:start/end-->` 슬롯(최신 4편)·`site/articles.html` 같은 슬롯(전체, 최대 12편). 두 블록은 derived라 루트 lastmod·R5·R7 무영향. 사이트맵은 모델 시리즈와 같은 규칙(내용 해시, `floor=publish`, weekly).
- **봇 연동**: `run_auto.sh`가 `site/articles`·`site/articles.html`을 스테이징(2026-10-06). prerender의 정리 루프에 `articles` 디렉터리 포함 — 원고를 지우거나 `publish`를 미래로 돌리면 다음 회차에 페이지가 사라진다. `index_watch._bucket`은 `/articles/`를 `article` 버킷으로 센다(색인 감시 대상에 자동 편입).
- **새 글 쓰는 법**: ① `article_data`류 분석으로 실측 수치 확보(모수 160개 지자체·9999 제외) ② md 작성 — 금칙(점추정·D-day·'소진 예상'·조건부 마감·WAV 최고액) 준수 ③ `python3 updater/prerender.py` + `selfcheck.py --warn-only`(생성된 글은 루트 페이지와 같은 금칙·광고 게이트 검사를 받는다) ④ 미래 `publish`는 커밋만 해 두면 된다. 발행 주기 목표: **주 1편 이상**(R9 = 최근 30일 ≥3편).
- **첫 발행분(2026-10-06 커밋)**: 10/6 추경 현황(160곳 회차 구조)·소진 속도 45일 실측 / 10/9 금액 상위 vs 물량 역관계 / 10/13 유형별 배정 실측 / 10/16 지방비 0원 셀 패턴 / 10/20 신청 실패 사례 7가지 / 10/23 17개 시도 잔여율 지도. about.html에 '업데이트 노트'(날짜별 변경 이력) 추가. **`related`의 href는 경로 그대로 출력된다(`sido:`·`region:` 접두어 미변환) — `sido/gangwon.html`처럼 쓴다.**

## 투명성 블록·정적 슬롯·피드·데이터 페이지 (2026-10-11, 알고리즘·벤치마크 리서치 반영)

- **배경**: 14-에이전트 리서치(구글 랭킹 시스템·애드센스 정책·벤치마크·네이버·기술/콘텐츠 감사 + 출처 검증)의 공통 결론 — 구글 2026 스팸 정책(scaled content·doorway, 2026-08-28 갱신)과 애드센스 '검토·선별 없는 자동 생성 금지' 조항 아래서 프로그래매틱 페이지의 방어선은 **페이지마다 다른 실측 수치 + 생성 방식·검수·정정의 공개**이고, 네이버(세션 81%)·무JS 수집기에는 **정적 HTML에 핵심 콘텐츠**가 있어야 한다.

## 정적 ↔ JS 재렌더 정합 · 에셋 캐시 버전 (2026-10-12, 콜드 로드 CLS 실측 대응)

콜드 로드(CSS·JS·JSON 전부 미캐시, 1024×768) 실측에서 지역 페이지 CLS 0.377이 나왔다. 원인 두 가지와 대응:

- **뱃지 라벨 불일치** — prerender `badge_of`와 app.js `statusBadge`의 문구가 달랐다('공단 등록 상태: 접수중' 병기 등). 데이터가 오면 JS가 뱃지를 다시 그리며 글자 수가 바뀌고, 모바일에선 줄 수가 바뀌어 아래 콘텐츠 전체가 밀렸다.
  → `badge_of(st, closed, over, cat)`를 statusBadge의 **쌍둥이**로 다시 썼다(규칙·문구 동일, 지역 상단 뱃지는 첫 방문자 기본 유형 `CAT_DEFAULT`='일반'). 한쪽만 고치면 다시 어긋난다 — 둘을 같이 고친다.
- **유형별 잔여 블록 미예약** — `.cats-slot` 예약 150px(모바일 280px) < 실제 203px(359px). → `cats_block()`이 app.js `categoryBar()+renderForecast()`와 같은 마크업을 **정적으로** 그린다(derived 마커 → lastmod 제외). detail.js는 같은 마크업으로 다시 그리므로 높이가 같다. categoryBar는 프리렌더된 고지(`[data-forecast]`)를 유지하고, renderForecast는 정적 고지가 있으면 이력 판정 결과로 한 번에 교체한다(중간 비움 금지). CSS의 `.cats-slot` 예약 높이는 제거.
- **잔여 추이 스파크라인 정적화** — `spark_block()`이 app.js `sparkline()`과 같은 SVG 마크업을 그린다(좌표는 JS `toFixed(1)`과 동일한 반올림 `_js_fixed1`). 빈 슬롯이 채워질 때 `.spark`의 margin-top 12px이 생기며 아래가 밀리던 잔여 시프트 제거 + 무JS 차트. CSS 예약은 `.spark-slot:empty`일 때만.
- **서버 판정 정본 `site/data/closed.json`** — 공지 마감 감지(`closed_map`)와 등록 회차 종료(`rounds_over`)를 prerender가 써 두고, app.js `withVerdict`가 status.json에 병합한다(`st.srv`). `closedInfo`·`statusBadge`가 이를 우선 사용 → JS 정규식 재감지와의 미세 차이(실측 3/160: 인천 2800·4691·4882)로 정적 뱃지와 JS가 어긋나던 모순이 사라진다. 파일이 없으면 JS 감지로 폴백. 등록 회차 종료(over) 지역은 JS도 '등록 회차 접수기간 종료' 뱃지를 쓴다(종전엔 JS만 초록으로 되돌렸음 — 59곳).
- **에셋 캐시 버전(P16-lite)** — `version_assets()`가 생성 페이지·슬롯 루트 페이지(index·status·sold-out·articles·data)의 자체 CSS/JS 링크에 내용 해시 `?v=xxxxxxxx`를 붙인다. GitHub Pages·Cloudflare의 `max-age=600` 때문에 배포 직후 10분간 새 HTML+옛 CSS/JS가 섞이던 창을 없앤다. 링크는 `<main>` 밖이라 lastmod 해시 무영향. 손편집 전용 루트 페이지(about·faq 등)는 대상 아님(봇 스테이징 밖).
- **검증 방법** — 로컬 프리뷰에서 160개 지역 페이지의 정적 뱃지·유형 블록을 `statusBadge`/`categoryBar` 실행 결과와 문자열 비교(공백·주석 정규화) → 불일치 0, 시도 표 54행·현황판 160행도 0. 라이브 CLS는 `PerformanceObserver({type:'layout-shift',buffered:true})`로 콜드(캐시 만료 10분 뒤) 측정 — 내장 브라우저에서 CSS를 네트워크로 받을 때만 보이는 'BODY 8→0px' 이동(0.37)은 측정 도구 아티팩트로 판단(표준 Chromium은 head 스타일시트가 렌더 차단). Lighthouse는 이 환경에서 헤드리스 Chrome 기동 불가 — PSI 키 또는 사용자 Chrome.
- **PSI 기준선(pagespeed.web.dev 웹 UI, Lighthouse 13.5, 모바일 느린 4G 에뮬, 2026-10-12 02:15)** — 지역 4113: 성능 62·접근성 90·권장 81·SEO 100, FCP 4.7s·LCP 8.0s·TBT 50ms·CLS 0·SI 5.9s / 홈: 66·91·100·100, FCP 3.9s·LCP 6.9s·TBT 120ms·CLS 0. CLS 0은 내장 브라우저의 BODY 이동이 도구 아티팩트라는 판단을 뒷받침한다. LCP 요소는 정적 cat-note(렌더 지연 2.3s — 서드파티 JS 장기 작업 6~7개와 경합, Inference). 남은 레버: 애드센스 로더(심사 중엔 정적 태그 유지 — 제거·동적 주입 금지), gtag 지연 로드, 렌더 차단 CSS(8.4KiB·310ms) 인라인화, 캐시 수명(Cloudflare 규칙·콘솔). 키 없이도 웹 UI로 측정 가능하니 재측정은 이 방법으로.
- **월간 리포트 집계 도구** — `/usr/bin/python3 updater/monthly_stats.py --month 2026-09 --md` (읽기 전용, stdlib). 월간 해설 원고의 수치는 이 출력에서 옮긴다.

## IndexNow 자동 제출 (네이버·빙)

- **무엇**: 페이지가 바뀌었을 때 검색엔진에 URL을 직접 알리는 공개 프로토콜. `api.indexnow.org` 한 곳에 보내면 참여 엔진(네이버·Bing·Yandex·Seznam 등) 전체에 공유된다. 구글은 미참여(사이트맵·GSC 경로 그대로).
- **언제**: `run_auto.sh`가 `OK 배포 완료` 직후 `updater/indexnow.py`를 호출. 실패는 `WARN indexnow 제출 실패(무시)` 한 줄로만 남고 배포 결과에는 영향 없음(fail-safe).
- **무엇을**: 이번 프리렌더에서 sitemap `<lastmod>`가 오늘로 움직인 URL만(`updater/.lastmod_changed.json`, prerender가 기록). 여기에 `https://evbojo.co.kr/` 호스트 + `site/sitemap.xml`에 있는 URL만 통과 → noindex·미발행 페이지는 절대 제출되지 않는다(헌법 I9 자동 정합).
- **중복 방지**: `updater/.indexnow_sent.json`에 URL별 마지막 수락일 기록, 같은 날 재제출 안 함(30일 지난 항목 자동 정리). 두 파일 모두 git 미추적 빌드 캐시.
- **키 파일**: `updater/indexnow.json`(`{"key","created"}`) + 공개 키 `site/<key>.txt`(내용 = 키 그대로, 줄바꿈 없음). IndexNow 키는 프로토콜상 공개 값이라 커밋 대상. 키 파일이 라이브(`https://evbojo.co.kr/<key>.txt`)에 올라가기 전엔 서버가 403 → 처음 켤 땐 키 파일부터 배포.
- **응답 코드**: 200/202 수락 · 400 형식 오류 · 403 키 불일치(키 파일 미배포) · 422 URL·호스트 불일치 · 429 과다 요청(경고만, 다음 회차 재시도).
- **수동 실행 / 최초 시드**

```bash
/usr/bin/python3 updater/indexnow.py --dry-run          # 이번 회차 제출 예정 목록만(네트워크 없음)
/usr/bin/python3 updater/indexnow.py --all --dry-run    # 사이트맵 전체 미리보기
/usr/bin/python3 updater/indexnow.py --all              # 최초 1회 시드: 사이트맵 전체 제출(당일 중복 제외, --force로 무시)
grep indexnow updater/auto.log | tail                   # 회차별 제출 결과
```

- **확인**: 네이버 서치어드바이저 → 요청 → IndexNow 현황(제출·처리 건수) / Bing Webmaster Tools → IndexNow. 반영까지 보통 수 시간~수 일.
- **키 교체**: `updater/indexnow.json`의 key를 새 값(`python3 -c "import secrets;print(secrets.token_hex(16))"`)으로 바꾸고 `site/<새키>.txt` 생성·옛 파일 삭제 → 배포. 재시드(`--all`)는 불필요.

## 장애 대응

- **`FAIL rebase 충돌`**: 다른 세션이 main을 고친 경우. 다음 회차에 자동 재시도되므로 보통 방치. 반복되면 수동으로 `git pull --rebase`.
- **`FAIL 수집 실패`**: ev.or.kr 점검/차단. fail-safe로 기존 데이터 유지됨. 14일 이상 지속 시 사이트에 자동 경고 배너.
- **라이브가 로컬보다 오래됨**: GitHub Pages 빌드 큐 지연이 원인일 수 있다(수 분~수 시간 걸린 사례 있음).
  `gh api repos/hlee-mrs/evbojo/pages/builds/latest`로 status 확인. `"building"`이 30분 이상이면
  `gh api -X POST repos/hlee-mrs/evbojo/pages/builds`로 재빌드 요청.
- **Cloudflare 캐시 의심 시**: `cf-cache-status` 헤더 확인(JSON은 기본 미캐시=DYNAMIC). HTML/JS 갱신이 안 보이면
  존 설정 browser_cache_ttl=0 유지 여부와 purge를 확인 (계정 Hlee@metlit.ai, 가이드 4장 참고).
- **⚠️ GitHub Pages "Enforce HTTPS"는 끈 상태 유지**: Cloudflare Flexible SSL 구조라 켜면 리다이렉트 루프로 사이트가 죽는다.
